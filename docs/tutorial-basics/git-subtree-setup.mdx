## Multi-Folder Git Subtree Sync

Git **Subtrees** let you share multiple folders (like `src/components`, `docs`, and `scripts`) across different repositories.  
Resources can be organized **inside folders** (recommended for clarity) or placed at the **root** of the shared repo.  
Both approaches work — the key is to use the correct `--prefix` path when adding the subtree.

---

### 🧩 Shared Repository Structure Options

<Tabs>
  <TabItem value="folders" label="Organized in Folders">

```bash
shared-resources/
├── src/components/
│   ├── Button.tsx
│   ├── Navbar.tsx
├── docs/
│   ├── getting-started.md
│   ├── api-reference.md
└── scripts/
    ├── build.sh
    ├── deploy.sh
```

  </TabItem>
  <TabItem value="root" label="Files at Root">

```bash
shared-resources/
├── Button.tsx
├── Navbar.tsx
├── getting-started.md
├── api-reference.md
├── build.sh
└── deploy.sh
```

  </TabItem>
</Tabs>

---

### 🪜 Setup Steps

<Tabs>
  <TabItem value="1" label="Add Remote">

```bash
git remote add shared https://github.com/ruseleredu/docusaurus-shared.git
```

  </TabItem>
  <TabItem value="2" label="Add Subtrees">

#### If resources are in folders:

```bash
git subtree add --prefix=src/components shared main --squash
git subtree add --prefix=docs shared main --squash
git subtree add --prefix=scripts shared main --squash
```

#### If resources are at root:

```bash
git subtree add --prefix=. shared main --squash
```

  </TabItem>
  <TabItem value="3" label="Pull Updates">

```bash
git subtree pull --prefix=src/components shared main --squash
git subtree pull --prefix=docs shared main --squash
git subtree pull --prefix=scripts shared main --squash
```

Or, if root:

```bash
git subtree pull --prefix=. shared main --squash
```

  </TabItem>
  <TabItem value="4" label="Push Changes">

```bash
git subtree push --prefix=src/components shared main
git subtree push --prefix=docs shared main
git subtree push --prefix=scripts shared main
```

Or, if root:

```bash
git subtree push --prefix=. shared main
```

  </TabItem>
</Tabs>

---

### 📊 Workflow Overview

| Setup       | Pros                                          | Cons                                    |
| ----------- | --------------------------------------------- | --------------------------------------- |
| **Folders** | Clear separation of components, docs, scripts | Slightly more commands to manage        |
| **Root**    | Simpler if only a few files                   | Can get messy with many mixed resources |

---

### ✅ Best Practices

- Prefer **folders** for clarity and scalability.
- Use `--squash` to keep history clean.
- Document the workflow in your site’s README so teammates know how to sync.
- Always **pull before pushing** to avoid conflicts.

## Sharing a Single File with Git Subtree

Git **Subtree** works at the **directory level**, but you can still share a single file by either:

- Placing it inside a dedicated folder (recommended for scalability).
- Keeping it at the root of the shared repo.

#### If file is inside a folder:

```

  </TabItem>
  <TabItem value="3" label="Pull Updates">

```

  </TabItem>
  <TabItem value="4" label="Push Changes">

git subtree push --prefix=deploy.sh shared main

  </TabItem>

---

### 📊 Comparison

| Setup      | Command                                                   | Best Use Case                     |
| ---------- | --------------------------------------------------------- | --------------------------------- |
| **Folder** | `git subtree add --prefix=scripts shared main --squash`   | When you may add more files later |
| **Root**   | `git subtree add --prefix=deploy.sh shared main --squash` | When you only need one file       |

---

### ✅ Best Practices

- Use a **folder** if you expect to add more shared files later.
- Root setup is fine for truly single‑file sharing.
- Always **pull before pushing** to avoid conflicts.
- Use `--squash` to keep history clean.
